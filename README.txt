Тестовые массивы Sortirovki_AA2508: разные размеры и разные данные

Всего 18 файлов с числами. В files.txt указаны их имена.
main выполняет 18 * 6 = 108 запусков. Изменять main не нужно.
Распакуйте содержимое архива в папку проекта с заменой старых TXT.

Названия best/average/worst обозначают благоприятный, обычный и тяжёлый
сценарии эксперимента. Размеры намеренно различаются. Эти тесты показывают
СОВМЕСТНОЕ влияние количества элементов и состава/порядка данных.
Они не являются сравнением лучших и худших случаев при фиксированном n.
При исследовании только порядка данных число элементов следует уравнять.
Ни одна сортировка не ускоряется только от увеличения размера массива.

Расчёска: 200 / 2000 / 10000 элементов.
best: возрастающий массив без обменов.
average: случайный порядок.
worst: сохранённый неблагоприятный массив из 10000 чисел, выбранный
по числу сравнений среди average и ещё 64 кандидатов.
Абсолютный худший случай по времени не доказан.

Гномья: 100 / 1000 / 10000 элементов.
best: короткий возрастающий массив.
average: случайная перестановка.
worst: длинный строго убывающий массив, максимальное число инверсий
для различных чисел такого размера, 49995000 соседних обменов.

Шейкерная: 100 / 1000 / 10000 элементов.
best: короткий возрастающий массив без обменов.
average: случайная перестановка.
worst: длинный строго убывающий массив с максимальным числом обменов.
В текущем алгоритме нет досрочного выхода при отсутствии обменов,
поэтому сравнения остаются квадратичными, даже когда обменов нет.
Время обратного массива может оказаться меньше времени случайного
при одинаковом n из-за особенностей выполнения на процессоре.

Пирамидальная: 500 / 5000 / 10000 элементов.
best: одинаковые числа 0.250000. Рекурсивные спуски heapify не требуются.
average: случайный порядок различных чисел.
worst: сохранённая неблагоприятная перестановка по числу сравнений,
выбранная среди average и 64 дополнительных кандидатов.
Она не гарантирует максимальное время среди всех возможных массивов.

Поразрядная: 10000 / 20000 / 30000 элементов.
best: большой массив однозначных целых значений от 1.000000 до 9.000000.
Формат double сохраняется. Алгоритм определяет scale=1, один разряд.
average: 20000 смешанных чисел с двумя знаками после точки,
до четырёх цифр в масштабированном целом.
worst: 30000 чисел с шестью знаками и модулями от 1 до 9.999999,
семь цифр после масштабирования, семь проходов по разрядам.
Выбрали большой благоприятный набор, чтобы показать применимость
поразрядной к объёмным данным. Большой размер не является причиной
лучшего случая и не означает меньшее абсолютное время.
Благоприятны малое число разрядов и подходящий диапазон значений.
Ограничения текущей radixSort: до шести знаков дробной точности,
масштабированные числа должны помещаться в int. Здесь они помещаются.
Используйте актуальную версию с llround.

size_100, size_1000, size_10000 сохранены без изменений.
Они имеют одинаковую точность и способ генерации, меньшие являются
начальными частями большего массива. По ним смотрим рост времени.

Один замер чувствителен к нагрузке, прогреву и оптимизации.
Для надёжного сравнения сделайте несколько прогонов и возьмите медиану.
Все 108 результатов должны совпадать с эталоном std::sort.
Содержимое файлов: только числа с точкой через пробел, без заголовка
и без отдельного числа размера.

Сборка: clang++ -std=c++17 -O2 *.cpp -o sorts
Запуск: ./sorts
